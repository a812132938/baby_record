# 业务规则

本文件记录用户可观察的判定、权限和数据语义。技术实现必须满足这些规则；具体代码边界见 [后端、数据与安全](../agent-instructions/backend-data-security.md) 和 [前端与离线同步](../agent-instructions/frontend.md)。

## 家庭、设备与宝宝资料

| 编号 | 规则 |
|---|---|
| `BR-ID-01` | 初始化数据库不得预置家庭、宝宝、用户或邀请码；第一个创建者成为 `ADMIN`。 |
| `BR-ID-02` | 邀请码是服务端生成的 32 位随机值；受邀设备加入后成为 `MEMBER`。 |
| `BR-ID-03` | 身份凭证只存在 HttpOnly Cookie；数据库仅存 token 的 SHA-256 hash。 |
| `BR-ID-04` | 客户端恢复时必须重放原始请求；服务端以同一 `creationKey + deviceId` 识别原操作，返回首次创建结果且忽略后续载荷，不得借重试改写家庭资料。确认成功后再次使用该 key 返回 `409`。 |
| `BR-ID-05` | 只有 `ADMIN` 可撤销其他设备；当前设备必须通过退出操作撤销自己。跨家庭设备不可见、不可撤销。 |
| `BR-BABY-01` | 昵称、出生日期、性别和出生体重均为必填；出生日期不得晚于今天。 |
| `BR-BABY-02` | 性别只允许 `BOY` / `GIRL`；出生体重范围为 100～15000 克，前端以 0.10～15.00 千克输入。 |
| `BR-BABY-03` | 出生当天为第 1 天；天数按本地自然日动态计算，不持久化。 |
| `BR-BABY-04` | 缺失资料必须由家长补录，禁止按昵称、历史记录或平均值推断。 |

## 喂养、睡眠与排泄

| 编号 | 规则 |
|---|---|
| `BR-FEED-01` | `FEED` 仅兼容旧版通用瓶喂；新记录使用 `DIRECT_BREASTFEED`、`BOTTLE_BREAST_MILK`、`FORMULA_FEED` 或 `PUMPING`。 |
| `BR-FEED-02` | 母乳瓶喂、配方奶及旧版瓶喂必须记录 1～1000 ml 的整数实际摄入量。 |
| `BR-FEED-03` | 亲喂不得填写毫升数；左右时长为非负整数，总时长为 1 秒～24 小时，结束侧必须有非零时长。 |
| `BR-FEED-04` | 亲喂存在 segments 时，分段左右合计和最后一侧必须与汇总字段一致。 |
| `BR-FEED-05` | 泵奶左右量均为非负整数，总量为 1～1000 ml，`amountMl` 必须等于左右之和；泵奶属于产出而非摄入。 |
| `BR-SLEEP-01` | 同一宝宝同一时刻最多有一条进行中的睡眠；重复开始返回现有睡眠。 |
| `BR-SLEEP-02` | 醒来时间不得早于入睡时间；重复结束已完成睡眠不得产生第二条记录。 |
| `BR-SLEEP-03` | 睡眠按与查询自然日的实际交集统计；恰在日界起点结束不计入当天。 |
| `BR-DAY-01` | 日期筛选使用半开区间 `[当天 00:00, 次日 00:00)`。 |
| `BR-POOP-01` | 便便记录保留颜色、性状和量；尿尿是一键事件，不伪造未填写属性。 |

## 幂等、冲突与同步

| 编号 | 规则 |
|---|---|
| `BR-SYNC-01` | 创建记录以 `(baby_id, client_event_id)` 唯一；重复请求只返回原 ID，不改写原内容。 |
| `BR-SYNC-02` | 修改和删除携带最初的 `expectedUpdatedAt`；版本不一致返回 `409`，客户端展示权威版本。 |
| `BR-SYNC-03` | 删除不存在的记录按幂等成功处理；不得因此重新创建或回滚其他记录。 |
| `BR-SYNC-04` | 同设备连续修改合并为最终意图，但保留最初版本；飞行中产生的新修改或删除不得被旧响应丢弃。 |
| `BR-SYNC-05` | 不可恢复的业务 4xx 只隔离对应 action；认证、冲突和可重试状态走各自恢复路径，不阻塞整条队列。 |
| `BR-SYNC-06` | SSE 只能通过 `publishChangedAfterCommit()` 的 `afterCommit` 回调在事务提交后通知；收到通知的设备重新读取权威数据。 |

## AI 会话

| 编号 | 规则 |
|---|---|
| `BR-AI-00` | AI 默认关闭；只有服务端显式启用且配置有效提供商密钥时，前端才展示入口。提供商地址必须使用 HTTPS，只有回环测试地址可使用 HTTP。 |
| `BR-AI-01` | 创建会话必须明确同意数据处理，并使用 `clientRequestId` 保证幂等；追问使用独立 `clientMessageId`。 |
| `BR-AI-02` | 快照以数据库时间为 cutoff，创建后不可变；只包含年龄、性别、出生体重和照护摘要，不含姓名或内部 ID。 |
| `BR-AI-03` | 快照被裁剪时必须在 `qualityNotes` 声明；不得把缺失数据补写成推测事实。 |
| `BR-AI-04` | 纯记录查询不联网；需要正常范围、风险或建议时，只能使用与宝宝数据隔离的固定通用主题检索。 |
| `BR-AI-05` | AI 不诊断、不开药、不泄露内部提示或快照原始数值；明确急症信号优先建议联系当地急救或尽快线下就医。 |
| `BR-AI-06` | 同一会话上一条分析未完成时拒绝新追问；只有 `FAILED` 会话可重试。 |
| `BR-AI-07` | 流式展示的最终文本必须与落库文本完全一致；归档会话时取消仍在等待的回复。 |
