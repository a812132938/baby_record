# 系统需求

本文件定义系统必须向用户提供的能力，是功能变更的验收基准。实现位置和技术约束见其他主题文档。新增需求应追加稳定编号，不要在技术文档里另写一份需求。

## 产品目标与角色

- 核心目标：打开即可看到宝宝当前状态，并在 1～2 次点击内完成常用记录。
- 未绑定设备：只能创建家庭或使用邀请码加入家庭。
- `ADMIN`：家庭创建者，除日常记录外可管理其他家庭设备。
- `MEMBER`：受邀家庭成员，可进入同一宝宝空间查看和记录。

## 身份、家庭与宝宝资料

| 编号 | 需求 |
|---|---|
| `SR-ID-01` | 首位用户可填写家庭、本人和宝宝资料，创建家庭并绑定当前设备。 |
| `SR-ID-02` | 家属可凭 32 位家庭邀请码和本人称呼绑定设备，进入同一家庭。 |
| `SR-ID-03` | 已绑定设备依靠长期 HttpOnly Cookie 自动恢复身份，无需账号密码。 |
| `SR-ID-04` | 家庭页可查看邀请码、设备和宝宝资料；管理员可撤销其他设备，当前设备可自行退出。 |
| `SR-BABY-01` | 可创建和修改宝宝昵称、出生日期、性别及出生体重，并按本地自然日显示“出生第 N 天”。 |

## 日常记录

| 编号 | 需求 |
|---|---|
| `SR-REC-01` | 支持母乳亲喂、母乳瓶喂、配方奶、泵奶、睡眠、便便和尿尿记录。 |
| `SR-REC-02` | 亲喂支持左右侧计时、切换、暂停、继续、完成和放弃，计时在重渲染及后台期间保持正确。 |
| `SR-REC-03` | 睡眠以“入睡/醒来”状态操作；当前睡眠持续时间在首页实时展示。 |
| `SR-REC-04` | 记录可选择时间、补录、编辑和删除；本地操作先反馈，不等待网络返回。 |
| `SR-REC-05` | 最近常用奶量按近 3 天使用频率和最近使用时间排序，自定义奶量自动参与后续排序。 |

## 首页、历史与统计

| 编号 | 需求 |
|---|---|
| `SR-VIEW-01` | 首页展示上次喝奶、上次便便、当前睡眠、今日分类型喂养汇总和今天时间轴。 |
| `SR-VIEW-02` | 首页时间轴严格使用本地自然日范围，不混入前一天或次日记录。 |
| `SR-VIEW-03` | 历史页可按日期、前一天和后一天查看完整记录，并可从该日期发起补录。 |
| `SR-VIEW-04` | 统计页展示最近 7 天的喂养、睡眠和排泄趋势，并可进入任一天明细。 |
| `SR-VIEW-05` | 亲喂、母乳瓶喂、配方奶和泵奶必须分开统计，不把泵奶产量计入宝宝摄入。 |

## 本地优先与多设备同步

| 编号 | 需求 |
|---|---|
| `SR-SYNC-01` | IndexedDB 是本地启动和离线记录主数据源；断网时核心记录功能仍可用。 |
| `SR-SYNC-02` | 网络恢复、页面回到前台或 SSE 重连后，待同步操作自动发送并与云端对账。 |
| `SR-SYNC-03` | 多设备写入提交后通过 SSE 通知其他设备刷新，不要求用户手动重载。 |
| `SR-SYNC-04` | 重复请求不得重复创建记录；并发编辑不得静默覆盖其他设备的更新。 |
| `SR-SYNC-05` | 不同部署、家庭和宝宝的本地缓存严格隔离。 |

## PWA 与 AI

| 编号 | 需求 |
|---|---|
| `SR-PWA-01` | 支持添加到主屏幕和 standalone 启动；静态 App Shell 可离线回退，API 响应不进入静态缓存。 |
| `SR-AI-00` | AI 是可选能力，默认关闭；未启用或未配置时不展示不可用入口，核心记录功能不受影响。 |
| `SR-AI-01` | 用户明确同意数据处理后，才可基于宝宝记录创建 AI 照护分析会话。 |
| `SR-AI-02` | 首次分析和追问均支持 SSE 流式展示，并可在断流时恢复到权威会话状态。 |
| `SR-AI-03` | 用户可查看会话历史、分析快照和来源状态，并可重试失败会话或删除/归档会话。 |
| `SR-AI-04` | AI 仅处理宝宝照护范围；需要一般参考时可独立检索可靠公开资料。 |

## 质量与运行要求

| 编号 | 要求 |
|---|---|
| `NFR-SEC-01` | 所有家庭和宝宝数据必须按当前设备身份及家庭/宝宝双重作用域隔离。 |
| `NFR-PRIV-01` | 发给 AI 的快照去标识化；联网检索不得携带宝宝数据、历史问答或用户原文。 |
| `NFR-DATA-01` | 离线、重试、响应丢失和多设备并发不得造成重复写入或无提示数据覆盖。 |
| `NFR-COMPAT-01` | 后端使用 Java 21；数据库变更同时兼容 MySQL 5.7.44 与生产 MariaDB。 |
| `NFR-OPS-01` | 配置与密钥外置，发布支持健康检查和自动回滚，PWA 入口文件不得被旧缓存长期固定。 |
