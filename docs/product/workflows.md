# 核心流程

本文件记录跨前后端的主路径、状态变化和异常闭环，不重复组件或类级实现。流程行为变化时同时更新系统需求、业务规则和相应测试。

## 家庭创建与恢复

1. 未绑定设备填写家庭名称、本人称呼、宝宝资料；客户端生成 `deviceId` 和 `creationKey`。
2. 服务端校验请求，在命名锁和事务内创建家庭、宝宝、管理员与设备，并签发 `br_device` Cookie。
3. 客户端用 `/auth/me` 核对响应身份，激活本地家庭/宝宝作用域，再调用创建确认接口清除恢复记录。
4. 若创建响应丢失，客户端持久化并原样重放请求；服务端按同一 key 和设备返回第一次创建的身份，后续载荷不能修改已提交资料。
5. 用户主动修改创建内容或更换设备时，客户端废弃旧恢复信息并生成新 key；确认后的旧 key 再用返回 `409`。

## 邀请加入与设备退出

1. 已绑定成员从家庭页取得邀请码并交给家属。
2. 家属提交邀请码、称呼和设备标识；服务端在命名锁内绑定为 `MEMBER` 并签发 Cookie。
3. 客户端激活对应家庭/宝宝本地作用域，加载 Dashboard 并建立 SSE。
4. 当前设备退出时撤销自身 token、清 Cookie 和本地身份状态；管理员撤销其他设备后，被撤销设备的后续认证失败。

## 新建记录与离线补发

1. 用户操作后，前端立即生成带 `clientEventId` 的本地事件，写入 Dexie，并加入 pending queue。
2. 在线时队列按当前家庭/宝宝身份发送；离线时保留，网络恢复或回到前台后继续。
3. 服务端校验租户和业务字段，幂等写入数据库，并在事务提交后发布 `changed`。
4. 客户端用响应中的服务端 ID/版本对账 pending 与本地事件，随后刷新 Query 数据。
5. 响应丢失时以同一 `clientEventId` 重试，服务端返回原记录而不重复写入。

## 编辑、删除与冲突

1. 用户编辑或删除时，前端先更新本地视图，并把服务器 ID 与原始 `expectedUpdatedAt` 写入 action。
2. 同设备的后续编辑折叠为最终意图；请求飞行中产生的新动作保留为依赖 action。
3. 服务端以 `id + baby_id + expectedUpdatedAt` 更新或删除。
4. 成功后客户端对账并刷新；记录已不存在的删除按成功收敛。
5. 版本冲突返回 `409`：停止覆盖，拉取云端权威记录并提示用户。
6. 不可恢复 4xx 仅回滚并隔离该 action；408/425/429 和网络失败继续退避重试。

## 睡眠状态

1. 点击“睡觉”时服务端锁定宝宝并查找进行中睡眠；已有记录则直接返回，没有才创建。
2. 点击“醒来”时以客户端事件 ID 或服务端睡眠 ID 结束同一记录，并保存结束操作人。
3. 结束时间早于开始时间时拒绝；重复结束返回已完成状态或按冲突收敛，不创建第二段睡眠。
4. 首页显示当前持续时间；历史和统计按各自然日交集切分跨午夜睡眠。

## 实时刷新与恢复

1. 写事务提交后，`RealtimeHub` 向同宝宝订阅者发送 `changed`。
2. 其他设备使 `['baby', babyId]` Query 缓存失效并重新读取 Dashboard/当前视图。
3. SSE 断开时指数退避重连；收到 connected、浏览器重新联网或页面回到前台时主动补一次权威数据对账。
4. 每次异步续行都验证 `identityEpoch`，身份已切换时丢弃旧家庭结果。

## 历史与统计

1. 首页只从本地今天半开区间生成时间轴和即时汇总。
2. 打开历史页时按日期请求完整事件集合，不依赖 Dashboard 的时间轴数量上限。
3. 打开统计页时在线读取服务端 7 日聚合，离线回退到本地历史计算。
4. 选择趋势中的某一天进入历史页；跨午夜睡眠按日界裁剪后分别计入。

## AI 会话

1. 服务端显式启用 AI 且配置有效提供商后，前端才展示入口；用户同意数据处理并提交幂等请求，服务端创建会话和待回复消息，状态进入 `ANALYZING`。
2. 服务端用数据库时间生成不可变去标识化快照；需要解释或建议时，先执行不带宝宝数据的通用主题检索。
3. 主请求使用快照、允许的历史和不可信参考上下文调用模型；token 经 `AiStreamHub` 推送，状态转为 `RESPONDING`。
4. 完成后先保证流式文本与持久化文本一致，再将会话置为 `READY`；失败则置为 `FAILED` 并记录错误码。
5. 前端流中断时轮询权威详情；仅失败会话可重试，归档会话会取消尚未完成的回复。
6. 定时恢复任务接管长期无进展且没有活动流的待处理消息，避免永久卡住。

部署和数据库升级流程见 [部署约束](../agent-instructions/deployment.md)；这里不重复运维步骤。
